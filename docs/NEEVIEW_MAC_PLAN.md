# YomiView macOS版 実装計画

このドキュメントは Claude Code が読んで実装するための仕様と作業計画です。上から順に読み、フェーズ単位で実装してください。判断に迷う点は「未決事項」に記録し、勝手に仕様を広げないでください。

---

## 1. 目的とスコープ

### 目的
Windows向けの画像・漫画ビューア「NeeView」の中核機能を、macOSネイティブのSwift（SwiftUI + 必要に応じてAppKit）で再実装する。

### MVPに含める機能
- フォルダ、ZIP、CBZ、PDFを「本」として開く
- 1ページ表示と見開き（2ページ）表示
- 右開き（日本の漫画向け）と左開きの切り替え
- キーボードとトラックパッドによるページ送り
- 先読みとキャッシュによる高速なページ送り
- 最近開いた本の記録と、最後に読んだページの復元
- フルスクリーン表示
- ドラッグ＆ドロップで開く

### MVPに含めない機能（後回し）
- RAR、7z形式の対応（後のフェーズで検討）
- Susieプラグイン、スクリプト拡張
- 画像の編集・補正フィルター
- サムネイルのスライダー表示などの細かい表示オプション
- App Store配布、公証（notarization）

---

## 2. 前提と制約

- **対象OS**：macOS 14 以降（SwiftUIの機能を使いやすくするため）
- **言語**：Swift 5.9 以降。Xcodeプロジェクトとして作成する
- **対象アーキテクチャ**：Apple Silicon（arm64）を優先。Intelも同じコードでビルドできるようにする
- **依存ライブラリ**：必要最小限にする。ZIP展開に ZIPFoundation（Swift Package Manager）を使う。それ以外は標準フレームワークを優先する
  - 画像のデコード：ImageIO
  - PDF：PDFKit
  - 画像の表示：SwiftUI の Image、または NSImage
- **ライセンス**：元のNeeViewはMITライセンス。このリポジトリもMITとし、`LICENSE` に NeeView の著作権表示（Ito Mitsuhiro）と MIT 全文を含める。NeeViewのコードを移植する場合は、その旨を `NOTICE.md` に記載する
- **Windows固有の機能は移植しない**（レジストリ、Windowsシェル連携など）
- **アプリ名・アイコン・画面デザインは独自のものにする**。NeeViewの名称・ロゴ・アイコンは使わない。アプリ名は `YomiView`（「読み」＋View。読書アプリであることが伝わる名前）とし、正式公開の前に既存アプリとの名称衝突を確認する

## 3. 参照元について

NeeViewのC#/WPFのソースコードは参考にしてよいが、機能の挙動を理解するための参照にとどめ、直接の翻訳はしないこと。実装は macOS の API に合わせて新たに書く。

NeeView の既知の挙動（参考）：
- フォルダやアーカイブ内の画像を、本のようにページ単位で閲覧する
- 見開きは「表紙は単独表示」など、ページ構成を調整できる
- 日本の漫画向けに右開きを標準として扱う

## 4. アーキテクチャ

```
YomiView/
├── App/
│   └── YomiViewApp.swift         // @main、WindowGroup、メニュー
├── Models/
│   ├── BookSource.swift          // 本の種類（フォルダ / ZIP / CBZ / PDF）を表す enum
│   ├── PageItem.swift            // ページ1枚の情報（表示名、インデックス、種類）
│   ├── ReadingDirection.swift    // 左開き / 右開き
│   └── ViewMode.swift            // 1ページ / 見開き
├── Sources/                      // 本の読み込み（プロトコルで抽象化）
│   ├── PageProvider.swift        // protocol PageProvider（ページ数、画像の取得）
│   ├── FolderPageProvider.swift
│   ├── ZipPageProvider.swift     // ZIP と CBZ は同じ実装でよい
│   └── PDFPageProvider.swift
├── Services/
│   ├── ImageCache.swift          // LRUキャッシュ + 先読み
│   ├── SpreadCalculator.swift    // 見開きのページ組み合わせ計算（純粋関数）
│   ├── NaturalSort.swift         // ファイル名の自然順ソート
│   └── RecentBooksStore.swift    // 最近開いた本と読書位置の保存（UserDefaults）
├── ViewModels/
│   └── ReaderViewModel.swift     // 現在のページ、表示モード、方向の状態
├── Views/
│   ├── ReaderView.swift          // メインの表示領域
│   ├── PageImageView.swift
│   ├── SpreadView.swift
│   └── SettingsView.swift
└── Tests/
    ├── SpreadCalculatorTests.swift
    ├── NaturalSortTests.swift
    └── PageProviderTests.swift
```

### 設計方針
- **状態は ReaderViewModel に集約**する。Viewは状態を表示するだけにする
- **ページの取得は PageProvider プロトコル経由**にする。フォルダ、ZIP、PDFの違いをViewに持ち込まない
- **見開きの計算は純粋関数（SpreadCalculator）に切り出す**。テストしやすくするため
- **画像は必ずダウンサンプリングして読み込む**。ImageIO の `CGImageSourceCreateThumbnailAtIndex` を使い、表示サイズに合わせて縮小する。元の巨大な画像を丸ごとメモリに載せない

## 5. 主要な仕様

### 5.1 本の読み込み
- フォルダ：直下の画像ファイル（png、jpg、jpeg、gif、webp、bmp、tiff、heic）を対象にする。サブフォルダは含めない
- ZIP / CBZ：アーカイブ内の画像エントリを対象にする。`__MACOSX/` や隠しファイル（`.` で始まるもの）は除外する
- PDF：PDFKit で開き、各ページを描画して表示する。描画時の解像度は表示サイズに合わせる
- ページの並びは **自然順ソート**（`page2.jpg` が `page10.jpg` より前に来る）。`localizedStandardCompare` を使う
- 対応していない形式は、エラーメッセージを表示して開かない

### 5.2 見開き表示
- 見開きの組み合わせは `SpreadCalculator` で決める
- 表紙（1ページ目）は単独表示をデフォルトとする
- 横長の画像（幅が高さより大きい）は単独表示にするオプションを設ける（デフォルトはオン）
- 右開きの場合、見開きの左右を入れ替える
- ページ数が奇数の場合、最後のページは単独表示にする

### 5.3 ページ送り
- 1ページ表示：1ページずつ進む
- 見開き表示：見開き単位で進む
- 次へ・前へ、先頭・末尾へのジャンプ
- 本の端を超えて送ろうとしたら何もしない（次の本へは自動で移動しない）

### 5.4 キーボード操作（初期値）
| 操作 | キー |
|---|---|
| 次のページ | →（右開きでは ←）、Space |
| 前のページ | ←（右開きでは →）、Shift+Space |
| 先頭 / 末尾 | Home / End |
| フルスクリーン切り替え | F |
| 見開き / 1ページ切り替え | M |
| 左開き / 右開き切り替え | D |

※キーの割り当ては将来、設定画面から変えられるようにする（MVPでは固定でよい）。

### 5.5 先読みとキャッシュ
- 現在のページの前後2ページ程度を先読みする
- キャッシュは件数の上限を設け、LRU（最も使われていないものから捨てる）で管理する
- 先読みはバックグラウンドで行い、表示をブロックしない

### 5.6 最近開いた本と読書位置
- 開いた本のパス、最後に読んだページ、見開き設定を `UserDefaults` に保存する
- 次に同じ本を開いたとき、最後に読んだページから再開する
- 最近開いた本は最大20件まで保持する

### 5.7 ウィンドウ
- フルスクリーン対応（macOS標準の仕組みを使う）
- ウィンドウのタイトルに本の名前と現在のページを表示する
- 画像の拡大・縮小：ウィンドウに合わせる（デフォルト）、原寸

### 5.8 エラー処理
- 壊れたZIP、読めないPDF、画像が1枚もない本は、エラー内容をユーザーに伝える
- 個別の画像の読み込みに失敗しても、本全体を止めない。そのページだけ「読み込めません」と表示する

## 6. 実装フェーズ

各フェーズの終わりに、ビルドが通り、テストが通ることを確認してからコミットしてください。コミットメッセージは `phase-N: 概要` の形式にします。

### Phase 0：プロジェクトの骨組み
- Xcodeプロジェクトを作成（macOS App、SwiftUI、deployment target 14.0）
- ZIPFoundation を Swift Package Manager で追加
- `LICENSE`、`NOTICE.md`、`README.md` を作成
- 空のウィンドウが表示されるところまで

**完了条件**：アプリが起動し、空のウィンドウが表示される。

### Phase 1：フォルダとZIP / CBZの閲覧（1ページ表示のみ）
- `PageProvider` プロトコルを定義
- `FolderPageProvider`、`ZipPageProvider` を実装
- `NaturalSort` を実装し、ユニットテストを書く
- ファイル選択ダイアログ（`NSOpenPanel`）から本を開ける
- ReaderViewModel で現在ページを管理し、←→ で送れる

**完了条件**：フォルダとZIP / CBZを開き、1ページずつ正しい順番で表示できる。

### Phase 2：PDF対応
- `PDFPageProvider` を実装（PDFKit）
- PDFを表示サイズに合わせた解像度で描画する
- 描画結果のキャッシュは Phase 4 で行うので、この段階では単純でよい

**完了条件**：15ページ程度のスキャン漫画PDFを開き、ページ送りできる。

### Phase 3：見開きと右開き
- `SpreadCalculator` を実装し、テストを書く（表紙単独、奇数ページ、横長ページ、右開きの入れ替え）
- `SpreadView` で2ページを並べて表示する
- M キーで見開きと1ページを切り替え、D キーで左右の開きを切り替える

**完了条件**：テストが全て通り、見開きと右開きが画面で正しく動く。

### Phase 4：先読みとキャッシュ
- `ImageCache` を実装（LRU、件数上限）
- 現在ページの前後を先読み
- ImageIO で表示サイズに合わせて縮小して読み込む

**完了条件**：連続してページを送っても、表示が止まらない。大きなPDFやZIPでもメモリが急増しない（アクティビティモニタで確認）。

### Phase 5：キーボード操作とフルスクリーン
- 5.4 のキー割り当てを実装
- F キーでフルスクリーン切り替え
- トラックパッドのスワイプでページ送り（任意）

**完了条件**：キー操作が仕様どおりに動く。

### Phase 6：最近開いた本と読書位置
- `RecentBooksStore` を実装
- 最後に読んだページを保存し、次回開いたときに復元
- 「最近開いた本」メニューを追加

**完了条件**：アプリを終了して再起動しても、直前のページから再開できる。

### Phase 7：ドラッグ＆ドロップとエラー処理
- フォルダ、ZIP、CBZ、PDFをウィンドウにドロップして開ける
- 壊れたファイルや画像のないアーカイブに対するエラー表示
- 個別ページの読み込み失敗時の表示

**完了条件**：不正なファイルを開いても、アプリが落ちずにエラーが表示される。

## 7. テスト方針

### 自動テスト（XCTest）
- `SpreadCalculator`：ページ数ごとの組み合わせ、表紙、横長ページ、右開き
- `NaturalSort`：数字を含むファイル名の並び順
- `PageProvider`：フォルダとZIPで、隠しファイルや `__MACOSX` が除外されること

### 手動確認（チェックリスト）
- [ ] フォルダ、ZIP、CBZ、PDFをそれぞれ開ける
- [ ] 1ページ表示と見開きが切り替わる
- [ ] 右開きで左右が正しく入れ替わる
- [ ] 表紙が単独表示になる
- [ ] 最後のページで止まる
- [ ] 再起動後に読書位置が復元される
- [ ] 連続でページを送ってもカクつかない
- [ ] 外付けドライブ上のファイルも開ける

## 8. Claude Codeへの作業指示

- フェーズの順に実装すること。フェーズをまたいで先の機能を作り込まない
- 各フェーズの完了条件を満たしてから次に進むこと
- 仕様に書かれていない挙動（例：キーの細かい割り当て、見た目）は、既存のmacOSアプリの慣習に合わせて決め、その判断を `DECISIONS.md` に記録すること
- NeeViewのC#コードをそのまま翻訳しないこと
- 依存ライブラリは ZIPFoundation 以外を追加する前に確認すること
- ビルドやテストが失敗したまま次のフェーズに進まないこと
- 実機で確認が必要な項目（描画の速さ、フルスクリーンの挙動など）は、実装後に人間が確認できるよう、確認手順をREADMEに書くこと
